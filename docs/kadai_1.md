課題 1d (基礎 / ex1d)
MyPlayer を、改良前の MyPlayer および RandomPlayer よりも強くなるように改良せよ。ここで、MyEval
における配列 M の数値を調整するとよい。M は、各マス目の重要度を表している。例えば、“M[0][0] = 10”
は、角のマス目の重みが 10 であり、そこに自石があることが好ましいことを意味する。一方、“M[0][1]
= -5” は、このマス目に着手しない方がよいことを表している。
実験プロトコル 改良が有効かを以下の手順で実験的に検証せよ。
1. 改良前の MyPlayer vs RandomPlayer を 100 局対戦させ、改良前の勝率を記録（ベースライン）。
2. 重み行列 M を調整した改良版 MyPlayer（仮に ImprovedPlayer と呼ぶ）を作成。
3. ImprovedPlayer vs RandomPlayer を 100 局対戦させ、改良後の勝率を記録。
4. ImprovedPlayer vs 改良前 MyPlayer を 100 局対戦させ、勝率を記録。
5. (1) と (3) の差、および (4) で 50% を超えているかを根拠に、改良が有効だったか判定せよ。
提出物 改良した MyEval.java、4 つの勝率と判定、採用した M の値の根拠を簡潔に（1 段落で）。
(注意) パッケージ ap26 内のプログラムの動作を変更するような改変をしないこと。

課題 1e (応用 / ex1e)
評価関数を改良せよ。例えば、局面 p に対する評価関数 ϕ(p) を次のように実装するとよい。変更前のプ
ログラムよりも強くなるように調整すること。
ϕ(p) = w1ψ(p) + w2lb + w3lw + w4nb + w5nw
ここで、ψ(p) は、MyEval クラスのような評価値計算表を用いた評価関数である。また、lb および lw は、
それぞれ局面 p における先手と後手の合法手の数である。nb および nw は、それぞれ局面 p における先手
と後手の石の数である。wi は各項の重みである。ϕ(p) = ∞ が自分の勝ちを表す場合、wi > 0 は、自分に
とって有利に働く項であることを表す。逆に、wi < 0 なら不利に働く項である。また、序盤、中盤、終盤
で、ψ(p) や wi を変化させるとよい。序盤、中盤、終盤の判定基準に関しては、試行錯誤するとよい。
余裕があれば、オセロに強くなるためのノウハウを収集し、それを実装するとよい。

課題 1f (応用 / ex1f)
move ordering を実装せよ。すなわち、盤面 p の子ノード q1, q2, ... において、ϕ(qi) がよい順に qi を探
索せよ。例えば、先手かつ ϕ(q3) > ϕ(q1) > ϕ(q2) の場合、q3, q1, q2 の順に探索するとよい。探索順序の決
定のために、例えば通常よりも浅く探索し、そこで得られた評価値を用いるとよい。
ここで、move ordering の精度と計算時間はトレードオフの関係にある点に注意する必要がある。move
ordering の精度を高めるために計算時間を使いすぎるのは本末転倒である。
